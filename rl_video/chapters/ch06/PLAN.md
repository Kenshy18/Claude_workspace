# 第6章 言語モデルを強化学習で鍛える（PPO・RLHF・GRPO） — 台本と演出プラン

目標尺: 約17分。前提: 第1〜5章すべて（特に 第1章「言語モデル＝方策」「軌跡＝トークン列」、第3章「TDとMCの中間」、第5章「ベースライン／アドバンテージ／Actor-Critic／方策オン」）。
この章で腹落ちさせたいこと:
1. 方策勾配の更新幅の問題 → 重要度比 r_t(θ) で古いデータを再利用 → PPO のクリップ（グラフで直感）。
2. GAE: TD と MC の間を λ で補間（第3章の回収）。
3. RLHF: 事前学習 → SFT → 報酬モデル（ブラッドリー・テリー）→ PPO＋KL ペナルティ。トークン単位の MDP（第1章の回収）。
4. 報酬ハッキング／過最適化と、KL が「命綱」である理由。
5. DPO（RL ループを使わない近道）を一言で。
6. GRPO と検証可能な報酬: グループ平均＝ベースライン（第5章の回収）、価値ネット不要。
7. シリーズ全体の地図とまとめ。

主な数式:
  r_t(θ) = π_θ(a_t|s_t) / π_{θ_old}(a_t|s_t)
  L^{CLIP}(θ) = E_t[ min( r_t(θ) Â_t , clip(r_t(θ), 1−ε, 1+ε) Â_t ) ]
  Â_t^{GAE} = Σ_{l≥0} (γλ)^l δ_{t+l}
  P(y_w ≻ y_l) = σ( r_φ(x, y_w) − r_φ(x, y_l) )
  L_RM = −log σ( r_φ(x, y_w) − r_φ(x, y_l) )
  R(x, y) = r_φ(x, y) − β log( π_θ(y|x) / π_ref(y|x) )
  GRPO: Â_i = ( r_i − mean(r_1..r_G) ) / std(r_1..r_G)

事実関係の注意（台詞はこの範囲を超えて断定しない）:
- PPO: Schulman ら 2017。ε は 0.2 がよく使われる。
- RLHF の3段階: InstructGPT（Ouyang ら 2022）の構成。
- 過最適化の曲線は模式図として描き、画面に「模式図」と明記する。
- DPO: Rafailov ら 2023。
- GRPO: DeepSeekMath（2024）で提案、DeepSeek-R1（2025）でも使用。
必要なら `chapters/ch06/helpers.py` を作る（`common/` は編集しない）。

## Scene: StepSize（約2分）
画面:
(1) 学習曲線: 順調に上がっていたのが、ある更新で急落し、そのまま戻らない（模式図でよいが、可能なら第5章のグリッドで学習率を大きくして実際に再現）。

N1: 前回、方策勾配法の弱点として、{A}更新の幅の難しさを挙げました。
N2: 勾配は、今の方策の、すぐ近くでだけ正しい方向を教えてくれます。{A}大きく動きすぎると、方策が壊れてしまう。しかも強化学習では、{B}壊れた方策で集めたデータで、次の学習をすることになります。教師あり学習のように、データセットが守ってくれないんです。
N3: 一方で、データを集めるのは高くつきます。言語モデルなら、{A}一つの回答を生成するのに、何百回もネットワークを動かします。集めたデータは、何度か使い回したい。
N4: 安全な範囲で、同じデータを、何度も使う。{A}これを両立させるのが、PPOです。

## Scene: Ratio（約2分）
画面: 古い方策 π_old（灰）と新しい方策 π_θ（紫）の確率の棒を並べ、ある行動の比 r = π_θ/π_old を表示。
重要度サンプリングの説明: 古い方策で集めたデータに、比を掛けて重み付けすると、新しい方策での期待値になる。
式: L(θ) = E_t[ r_t(θ) Â_t ]、θ = θ_old では r = 1 で、勾配が第5章の方策勾配と一致（∇r = ∇π/π_old = ∇log π）。
N1: まず、データの使い回しです。{A}データを集めたときの、古い方策と、今、学習中の新しい方策。その確率の比を、{B}[r_t|アールティー]とします。
N2: 古いデータで計算した値に、この比を掛けると、{A}新しい方策で集めたかのように、補正できます。重要度サンプリングと呼ばれる、統計の古典的な道具です。
N3: この比に、アドバンテージを掛けたものを、目的関数にします。{A}新旧の方策が同じなら、比は1で、その勾配は、前回の方策勾配と、ぴったり一致します。
N4: ただし、{A}比が1から大きく離れると、この補正は、とたんに当てにならなくなります。新しい方策が、古いデータの外側へ、どんどん出て行ってしまうからです。

## Scene: Clip（約2分半） ← 山場1
画面: 2枚のグラフ（横軸 r、縦軸 目的関数の値）を左右に。
 左: Â > 0 のとき。r·Â の直線と clip 版を重ね、min を取った太線は r = 1+ε で平らになる。
 右: Â < 0 のとき。min を取った太線は r = 1−ε より左で平らになる。
 ε = 0.2 の目盛り。r = 1 に縦の点線。
 平らな部分で「勾配 0」、ボールを転がして止まる演出。
式: L^{CLIP} = E_t[ min( r_t Â_t , clip(r_t, 1−ε, 1+ε) Â_t ) ]
N1: そこで、PPOは、{A}比に、はさみを入れます。比が、1マイナス、イプシロンから、1プラス、イプシロンの範囲を出たら、切り落とすんです。イプシロンは、よく0.2が使われます。
N2: グラフで見てみましょう。{A}アドバンテージがプラス、つまり、良かった行動の場合です。確率を上げるほど、目的関数は増えますが、{B}1.2倍を超えたところで、平らになります。それ以上上げても、得をしない。
N3: {A}アドバンテージがマイナス、つまり、悪かった行動の場合は、逆です。確率を下げると得をしますが、{B}0.8倍を下回ったところで、平らになります。
N4: 平らなところでは、{A}勾配が0なので、それ以上、方策は動きません。一回のデータで、確率を大きく変えすぎないように、自然とブレーキがかかるわけです。
N5: マックスではなく、{A}ミニマムを取っているのもポイントです。目的関数が得をする方向の変化だけを、切り落とす。悲観的に見積もることで、安全側に倒しているんです。
N6: これで、同じデータで、何回か勾配を計算し直しても、{A}方策は、古い方策の近くにとどまります。PPOは、実装が簡単で、しかも安定していることから、強化学習の定番になりました。

## Scene: GAE（約1分半）
画面: δ_t, δ_{t+1}, δ_{t+2}, … の棒に、重み (γλ)^l を掛けて足すアニメーション。λ のスライダー: λ=0 で最初の1本だけ（TD）、λ=1 で全部（MC）。第3章のヒストグラム（MC 幅広、TD 幅狭）を小さく再掲。
式: Â_t = Σ_{l≥0} (γλ)^l δ_{t+l}
N1: アドバンテージの見積もり方も、一つ紹介しておきます。{A}第3章で、TDとモンテカルロの間を取る方法がある、と言いました。
N2: 一歩ごとのTD誤差を、{A}先の方ほど、ガンマ・ラムダ倍ずつ小さくして、足し合わせます。{B}ラムダが0なら、最初の一歩だけ。つまりTD。{C}ラムダが1なら、最後まで全部。つまりモンテカルロ。その間で、ばらつきと偏りのバランスを取ります。
N3: これを、一般化アドバンテージ推定、GAEと呼びます。PPOと組み合わせて使うのが、定番です。

## Scene: RewardModel（約2分）
画面: 同じ質問への2つの回答（吹き出し A, B）。人のアイコンが A を選ぶ。
報酬モデル（箱）が、各回答にスコア r_φ を出す → 差 r_A − r_B → シグモイド曲線 σ で「A が好まれる確率」に。
式: P(y_w ≻ y_l) = σ( r_φ(x,y_w) − r_φ(x,y_l) )、L = −log σ( r_φ(x,y_w) − r_φ(x,y_l) )
N1: 報酬モデルの学習は、{A}比較のデータから行います。同じ質問への二つの回答と、人が選んだ方。
N2: 報酬モデルは、{A}回答ごとに、一つの数字、スコアを出します。{B}二つのスコアの差を、シグモイド関数に通したものを、{C}「人がこちらを選ぶ確率」とみなします。ブラッドリー・テリー・モデルと呼ばれる、スポーツのレーティングなどでも使われる考え方です。
N3: あとは、人が選んだ方の確率が高くなるように、{A}交差エントロピーで学習するだけ。スコアの絶対値ではなく、差だけが意味を持つ、というのがポイントです。

## Scene: TokenMDP（約2分）
画面: プロンプト＋生成中のトークン列（第1章の系列の見た目で）。各トークンの下に報酬の枠: 途中はほぼ0（KL ペナルティの小さな負の値が並ぶ）、最後に報酬モデルのスコア。
その下に価値ヘッド（クリティック）の出力 V(s_t) の小さな折れ線 → GAE でトークンごとのアドバンテージ（赤／緑）。
式: R(x,y) = r_φ(x,y) − β log( π_θ(y|x) / π_ref(y|x) )
N1: 強化学習の部分を、第1章の言葉で書き直してみましょう。{A}状態は、質問と、ここまでに生成したトークン。行動は、次のトークン。{B}回答を最後まで生成したところで、報酬モデルのスコアが、報酬として届きます。
N2: 報酬が、{A}何百トークンも後に、一度だけ届く。第1章で見た、信用割り当て問題そのものです。{B}そこで、各トークンの時点での価値を見積もるクリティックを用意し、GAEで、トークンごとのアドバンテージを計算します。第5章の、アクター・クリティックです。
N3: そして、もう一つ、大事な項があります。{A}元のモデルからどれだけ離れたか、を表す、KLダイバージェンスのペナルティです。

## Scene: RewardHacking（約2分）
画面:
(1) 報酬モデルの「弱点」の例: 長い回答ほどスコアが高い傾向 → 方策が、中身のない長文や、決まり文句を繰り返すようになる（吹き出しがどんどん長くなる）。
(2) 模式図: 横軸「元のモデルからの KL」、縦軸「報酬」。報酬モデルのスコア（上がり続ける）と、本当の品質（途中から下がる）。右上に「模式図」。
(3) 分布の図: 参照モデル π_ref（灰）から π_θ（紫）がずれていく。KL の「命綱」が引っ張り戻す。
N1: なぜ、KLのペナルティが必要なのでしょうか。
N2: 報酬モデルは、{A}人の好みを、限られたデータから真似しただけの、不完全なものさしです。強化学習は、そのものさしの点数を、とにかく上げようとします。{B}すると、ものさしの穴を突く方法を、見つけてしまうんです。例えば、長い回答ほど点数が高くなる癖があれば、{C}中身のない長文を書くようになる。報酬ハッキングと呼ばれる現象です。
N3: {A}元のモデルから離れるほど、報酬モデルのスコアは上がり続けますが、{B}本当の品質は、あるところから、下がり始めます。
N4: KLのペナルティは、{A}元のモデルから離れすぎないようにする、命綱です。人間らしい文章を書く力は、事前学習とSFTで身につけたもの。{B}そこから大きく外れた場所では、報酬モデルは、もはや信用できないからです。
N5: ちなみに、このKL付きの目的関数は、最適な方策の形を、式で書き下せます。それを利用して、強化学習のループを使わずに、{A}比較データから直接、方策を学ぶ、[DPO|ディーピーオー]という方法も広く使われています。

## Scene: GRPO（約2分半） ← 山場2
画面: 数学の問題（例: 「1から100までの整数の和は？」）に、モデルが8つの回答をサンプル（8つの吹き出し、最後の答えだけ見える）。正解（5050）に ✓ で報酬 1、不正解に ✗ で 0。
グループの平均（例 3/8 = 0.375）と標準偏差を計算 → 各回答のアドバンテージ（正解 +1.29、不正解 −0.77 など、実際に計算）。棒グラフで赤／緑。
第5章のベースラインの図を小さく再掲して「グループの平均＝ベースライン」。
式: Â_i = ( r_i − mean(r) ) / std(r)
最後に「価値ネットワーク（クリティック）なし」の図: PPO の図からクリティックの箱が消える。
N1: 最近では、{A}答えが正しいかどうかを、機械的に確かめられる問題でも、強化学習がよく使われます。数学の問題の、最終的な答え。プログラムが、テストに通るかどうか。{B}検証可能な報酬、と呼ばれます。
N2: ここでよく使われるのが、{A}[GRPO|ジーアールピーオー]という方法です。同じ問題に対して、{B}回答を、何通りもサンプルします。この例では8通り。そのうち、{C}正解したものに報酬1、それ以外に0を与えます。
N3: そして、{A}グループの中での平均を引き、標準偏差で割ったものを、アドバンテージにします。{B}平均より良かった回答は、確率を上げ、{C}平均より悪かった回答は、下げる。
N4: 見覚えがありますね。{A}第5章のベースラインを、同じ問題への、ほかの回答の平均で代用しているんです。こうすると、{B}巨大な言語モデルと同じ規模の、価値ネットワークを、別に用意しなくて済みます。
N5: 正しいかどうかだけを報酬にして、こうした強化学習を続けると、{A}モデルが、自分で検算したり、途中で考え直したりする、長い推論を身につけていった、という報告もあります。誰も、考え方そのものを、教えていないのに、です。
