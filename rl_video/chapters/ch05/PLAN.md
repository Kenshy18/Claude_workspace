# 第5章 方策を直接動かす（方策勾配法） — 台本と演出プラン

目標尺: 約15分。前提: 第1章（途切れた勾配の図、J(π)=E[G_0]、言語モデル＝方策、softmax）、第2〜3章（V, Q, TD誤差）、第4章（max が取れない行動空間）。
この章で腹落ちさせたいこと:
1. 方策をパラメータ化（softmax の logits）。
2. 対数微分トリック ∇p = p ∇log p で、勾配が「期待値」になり、サンプルで推定できる。
3. log p_θ(τ) を展開すると、環境の項が θ に依存せず消える ——「途切れた道」が迂回できた瞬間（第1章の回収）。
4. REINFORCE = 自分でサンプルした行動を「正解ラベル」とみなし、リターンで重み付けした最尤推定（交差エントロピーとの対比）。
5. 因果性（reward-to-go）、ベースラインで分散を下げても不偏（Σ_a ∇π = 0）、アドバンテージ A = G − V。
6. Actor-Critic: 価値ベース（第2〜4章）と方策ベースの合流。TD誤差をアドバンテージの推定に。
7. 方策オン型であること、1回の更新幅の難しさ → 第6章（PPO）へ。

主な数式:
  J(θ) = E_{τ∼p_θ}[R(τ)] = Σ_τ p_θ(τ) R(τ)
  ∇J = Σ_τ ∇p_θ(τ) R(τ) = Σ_τ p_θ(τ) ∇log p_θ(τ) R(τ) = E[ ∇log p_θ(τ) R(τ) ]
  log p_θ(τ) = log ρ(s_0) + Σ_t [ log π_θ(a_t|s_t) + log P(s_{t+1}|s_t,a_t) ]
  ∇J = E[ Σ_t ∇log π_θ(a_t|s_t) G_t ]
  E_{a∼π}[ ∇log π_θ(a|s) b(s) ] = b(s) ∇ Σ_a π_θ(a|s) = b(s) ∇1 = 0
  ∇J = E[ Σ_t ∇log π_θ(a_t|s_t) ( G_t − V(s_t) ) ]
  Actor-Critic: A_t ≈ δ_t = r_{t+1} + γV(s_{t+1}) − V(s_t)

図の数値（1次元ガウス方策の例、分散の比較、グリッドでの学習曲線）は実際に計算する。
必要なら `chapters/ch05/helpers.py` を作る（`common/` は編集しない）。

## Scene: Parametrize（約1分40秒）
画面: あるマスの4つの logits z（上右下左、桃色の数値）→ softmax → 確率の棒（紫）。logit のスライダーを動かすと棒が連動（ValueTracker）。
式: π_θ(a|s) = exp(z_a) / Σ_b exp(z_b)、z = z_θ(s)
最後に「z_θ はニューラルネット（第1章の言語モデルと同じ）」と小さく。

N1: まず、方策を、{A}パラメータで表します。
N2: 各行動に、{A}ロジットと呼ばれる、好き嫌いの点数を割り当てて、{B}ソフトマックスで確率に変換します。分類モデルの出力層と、まったく同じです。
N3: {A}右のロジットを上げれば、右を選ぶ確率が上がり、{B}ほかの確率は、そのぶん下がります。確率の合計は、いつも1です。
N4: ロジットは、状態を入力とするニューラルネットで計算してもいいですし、この小さな世界なら、マスごとの表でも構いません。いずれにしても、目標は一つ。{A}期待リターン[J|ジェー]が大きくなる方向に、パラメータを動かすことです。

## Scene: ScoreFunction（約3分） ← この章の山場
画面:
(1) J = Σ_τ p_θ(τ) R(τ): 横軸に「ありうる軌跡」をずらりと並べた棒グラフ（高さ = 確率 p_θ(τ)、色 = R(τ) の良し悪し）。J はその重み付き和。
(2) ∇ を入れると、∇p_θ(τ) が出てくる。「これは期待値の形ではない＝サンプルでは推定できない」ことを強調（全軌跡の和が必要）。
(3) 対数微分トリック: ∇p = p ∇log p を、(log p)' = p'/p から1行で導く（TransformMatchingTex）。
(4) 代入して E[ ∇log p_θ(τ) R(τ) ] に。「期待値に戻った → サンプルの平均で推定できる」。
(5) log p_θ(τ) を展開: log ρ(s0) + Σ[ log π_θ(a_t|s_t) + log P(s_{t+1}|s_t,a_t) ]。
    θ で微分すると、初期分布と遷移確率の項は θ を含まないので 0 → 灰色にして消す（×が消えていく演出）。
(6) 残るのは方策の項だけ: ∇J = E[ Σ_t ∇log π_θ(a_t|s_t) R(τ) ]。
    第1章の計算グラフに戻り、途切れた矢印の上を、紫の迂回路（曲線矢印）が通る。

N1: 期待リターンを、{A}ありうるすべての軌跡についての和で書いてみます。それぞれの軌跡が起きる確率に、その軌跡のリターンを掛けて、足し合わせたものです。
N2: 軌跡の確率は、{A}方策のパラメータによって変わります。だから、パラメータで微分すると、{B}確率の微分が出てきます。
N3: ここで困ったことがあります。この式は、{A}すべての軌跡についての和で、期待値の形をしていません。つまり、実際にロボットを走らせて得たサンプルの平均で、代わりにすることができないんです。
N4: そこで、一つトリックを使います。{A}対数の微分は、元の関数の微分を、元の関数で割ったもの。これを並べ替えると、{B}確率の微分は、確率かける、対数確率の微分、と書けます。
N5: これを代入すると、{A}確率が、外に出てきました。確率を掛けて足しているので、これは、{B}期待値です。サンプルの平均で、推定できる形に戻ったわけです。対数微分トリック、と呼ばれています。
N6: 次に、軌跡の対数確率を、中身に分解してみましょう。軌跡の確率は、最初の状態の確率と、{A}方策が行動を選ぶ確率と、{B}環境が次の状態を選ぶ確率の、掛け算です。対数を取ると、足し算になります。
N7: さあ、ここが一番大事なところです。これを、パラメータで微分すると、{A}最初の状態の確率も、環境の遷移確率も、パラメータを含んでいないので、{B}消えてしまいます。
N8: 残るのは、{A}方策の項だけ。環境の中身を知らなくても、微分できなくても、関係ない。{B}途切れていた道が、つながりました。
N9: 自分が選んだ行動の、対数確率の勾配に、リターンを掛けて、平均する。これが、{A}方策勾配定理の、もっとも基本的な形です。

## Scene: Intuition（約2分）
画面: 1次元の連続行動の例。方策 = 平均 μ のガウス分布（紫の山）。報酬関数 R(x)（黄の曲線、右の方に山）。
サンプル x_i を落とし、各サンプルに「分布をその点に寄せる矢印」を、R(x_i) に比例した長さで描く。
良い点の矢印が長く、全体として山が右へ動く。これを数ステップ繰り返し、μ が報酬の山へ移動する（実際に計算: ∇_μ log N(x; μ, σ²) = (x−μ)/σ²）。
後半: 交差エントロピーとの対比の式を2行で:
  教師あり: ∇ log π_θ( y | x )            （y は正解ラベル）
  方策勾配: ∇ log π_θ( a_t | s_t ) · G_t   （a_t は自分で選んだ行動）

N1: この式の意味を、絵で見てみましょう。{A}方策が、行動の上の、こんな山の形の分布だとします。そして、{B}報酬は、右の方の行動ほど大きい、としましょう。
N2: 方策から、{A}いくつか行動をサンプルします。対数確率の勾配は、{B}分布を、その点に寄せる方向を向いています。それに、リターンを掛けるので、{C}良い結果を出した点ほど、強く引き寄せます。
N3: 全部を平均すると、{A}分布は、報酬の高い方へと、少しずつ動いていきます。
N4: 機械学習エンジニアなら、この形に、見覚えがあるはずです。{A}教師あり学習の、交差エントロピーの勾配は、正解ラベルの対数確率の勾配でした。
N5: 方策勾配では、{A}自分がサンプルした行動を、正解ラベルだと思って学習します。ただし、{B}うまくいった分だけ強く。つまり、リターンで重み付けした、最尤推定なんです。このアルゴリズムは、{C}[REINFORCE|リインフォース]と呼ばれています。

## Scene: Causality（約1分）
画面: エピソードのタイムライン。時刻 t の行動から、それより前の報酬へ向かう矢印に×。R(τ) → G_t（reward-to-go）に置き換わる。
式: ∇J = E[ Σ_t ∇log π_θ(a_t|s_t) G_t ]

N1: 一つ、簡単な改良ができます。{A}ある時刻の行動は、それより前にもらった報酬には、影響を与えられません。過去は変えられないからです。
N2: だから、各時刻の行動に掛けるのは、軌跡全体のリターンではなく、{A}その時刻から先のリターンで十分です。余計な項を減らすと、推定のばらつきも減ります。

## Scene: Baseline（約2分半）
画面:
(1) 1次元ガウスの例で、報酬を全部 +5 底上げ（R(x)+5）。すべてのサンプルが「引き寄せ」になり、矢印が全部同じ向き → 勾配の推定値がばらつく。
    勾配推定値のヒストグラム（多数回のバッチで実際に計算）: 底上げなし／ありで幅が大きく違う。
(2) ベースライン b を引く: R − b。平均より良い点は引き寄せ、悪い点は押しのける（赤い矢印）。ヒストグラムが細くなる（実際に計算して、分散の比を数字で表示）。
(3) なぜ引いてもいいのか: E_a[∇log π(a|s) b] = b ∇ Σ_a π(a|s) = b ∇1 = 0 を3行で。確率の棒の合計が1で一定 → 全体を持ち上げる方向は存在しない、という絵（棒が一本上がれば他が下がる）。
(4) b = V(s) → A = G − V(s)：アドバンテージ（赤／緑で符号表示）。

N1: ただし、[REINFORCE|リインフォース]には、大きな弱点があります。{A}推定のばらつきが、とても大きいんです。
N2: 例えば、{A}報酬を全部、5ずつ底上げしてみます。問題の本質は、何も変わっていません。でも、{B}すべてのサンプルのリターンがプラスになるので、どの行動も、引き寄せられる方向に押されます。{C}どれを、どれだけ押すかの、わずかな差でしか、正しい方向が分からない。推定値は、大きくばらつきます。
N3: そこで、{A}リターンから、ある基準値を引きます。ベースラインです。{B}平均より良かった行動は引き寄せ、{C}平均より悪かった行動は、押しのける。
N4: 基準値を引いてしまって、答えが変わらないのでしょうか。{A}実は、変わりません。基準値が行動によらなければ、その項の期待値は、{B}確率の合計の微分、つまり、{C}1の微分になって、0だからです。確率は、どれかを上げれば、どれかが下がる。全体を持ち上げる方向は、そもそも存在しないんです。
N5: 平均を変えずに、ばらつきだけを減らせる。{A}実際に計算してみると、ばらつきは、このくらい小さくなります。
N6: 基準値には、{A}その状態の価値、[V|ブイ]を使うのが自然です。リターンから価値を引いたものを、{B}アドバンテージと呼びます。「平均と比べて、どれだけ良かったか」を表す量です。

## Scene: ActorCritic（約2分）
画面: 2つの箱:「アクター（方策 π_θ）」紫と「クリティック（価値 V_φ）」青緑。
環境 → (s, a, r, s') → クリティックが TD誤差 δ を計算 → アクターへ「この行動は予想より良かった/悪かった」→ アクター更新。クリティックも δ で更新。
式: A_t ≈ δ_t = r_{t+1} + γV_φ(s_{t+1}) − V_φ(s_t)
「第2〜4章（価値）」と「第5章（方策）」の2本の道がここで合流する図（第1章ロードマップの2本の枝が合流）。

N1: では、その価値は、どうやって手に入れるのか。{A}第3章の、TD学習で学べばいい。
N2: 方策を動かす役を、{A}アクター。価値を見積もる役を、{B}クリティックと呼びます。
N3: クリティックは、{A}一歩進むたびに、TD誤差を計算します。予想より良かったか、悪かったか。{B}これを、アドバンテージの見積もりとして、アクターに渡します。エピソードの最後まで待つ必要も、ありません。
N4: 価値を学ぶ道と、方策を学ぶ道。{A}第1章で分かれた二本の道が、ここで合流しました。アクター・クリティックは、現代の強化学習の、ほとんどの手法の土台になっています。

## Scene: Demo（約1分半）
画面: いつものグリッド。各マスに、確率に比例した太さの4本の矢印（紫）。最初は一様（4本とも同じ細さ）。
アドバンテージ付き REINFORCE（または Actor-Critic）を実際に学習させ、矢印の太さが変化していく様子を早回し。右下に学習曲線（エピソードの平均リターン）。
最後、ほぼ決定的な矢印になり、第2章の最適方策とほぼ一致（違いがあれば正直に）。

N1: いつもの世界で、試してみましょう。{A}最初は、どのマスでも、四つの方向を同じ確率で選びます。
N2: 学習が進むにつれて、{A}良い方向の矢印が、だんだん太くなっていきます。{B}価値を経由せずに、方策そのものを、少しずつ変えていく。これが、方策勾配法です。

## Scene: Outro（約1分）
画面: 学習曲線が、途中で急落する例（大きすぎる更新で方策が壊れ、その方策で集めたデータも悪くなる）。「データは使い捨て（方策オン）」のアイコン。
N1: ただし、方策勾配法には、扱いの難しいところがあります。{A}一度に大きく更新しすぎると、方策が壊れてしまい、{B}その壊れた方策で集めたデータで、また学習することになるんです。教師あり学習と違って、データセットが、自分の失敗で汚れてしまう。
N2: しかも、集めたデータは、{A}その時点の方策でしか使えません。方策を少し変えるたびに、データを集め直す必要があります。
N3: 更新を、安全な範囲にとどめながら、集めたデータを、できるだけ有効に使いたい。{A}その答えが、最終章の主役、PPOです。そしてそれは、大規模言語モデルの学習へと、まっすぐつながっていきます。
